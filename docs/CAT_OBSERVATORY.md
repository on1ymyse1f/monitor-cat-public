## 第二主题：夜想（Nocturne）与本地角色包（`Skins.swift`）

设置 → 外观 → 主题 可在「猫娘观测所」与「夜想」之间切换。颜色经 `Theme` 在绘制时读取当前主题的调色板，
视图本身不感知主题；只有形状不同的几个母题按主题切换：标记（肉球 / 新月）、选中标签的药丸（猫耳 / 呆毛）、
英雄区背景（聚光灯 + 集中线 / 月光 + 金色星光 + 花瓣）、窗口底纸（漫画原稿纸 / 星夜）。夜想始终为深色。

夜想的配色取自一套角色表情图集：紫黑底、淡紫粉发色、深红玫瑰、“！”的金色与“？”“Zzz”的薰衣草色。
角色本身来自**本地角色包**：

```sh
python3 scripts/make-character-skin.py 表情图集.png --name <包名> --title "<显示名>" --map moods.json
```

脚本按白色间隔自动切格，每格生成边缘羽化、融入夜色的肖像（大尺寸用）与带淡紫描边的圆形头像（小尺寸用），
并写入 `skin.json`（`moods.json` 指定哪一格扮演哪种猫娘情绪，键为 `MascotState.Mood` 的原始值）。
角色包放在 `~/Library/Application Support/AIMonitor/Skins/<包名>/`，App 只从这里读取。

**角色图不进仓库。** 他人拥有的角色插画可以放在自己的 Mac 上用，但不应由这个公开仓库分发：
脚本拒绝写入任何 git 工作树，App 不打包任何角色图。未安装角色包时夜想暂用猫娘；
角色包未映射的情绪也回落到猫娘。

### 夜想为长夜月所做的专属细节（0.8.1）

依据公开资料整理的角色设定（《崩坏：星穹铁道》3.6 实装；记忆命途、冰属性；三月七的“影”与“镜中人”；
意象为夜、月、记忆、烛火、雾、时间与守护），每一处细节都对应一条设定，而不是泛用装饰：

| 设定 | 界面里的样子 |
|---|---|
| 三月七的“镜中人”，名字里的“月” | 首页英雄区：她站在一面圆形手镜里，镜子同时是一轮满月——银色镜框、发饰样式的四颗菱形镶钉、月光镜面与一道高光。镜面遮罩静止，她在镜中动 |
| 冰属性 | 调色板加入霜蓝；星光里混入六瓣冰晶；额度告急时，漫画的冲击爆炸换成冰晶迸裂，卡片从角落裂开镜纹 |
| 时间 | 夜想里额度环带十二道时钟刻度——它本来就在倒数重置时间 |
| 长夜与月 | 标题旁显示当晚真实月相（按平均朔望月计算，悬停显示名称）；菜单栏图标换成月与星；问候语按时段为“晨光熹微 / 午后微光 / 夜幕降临 / 长夜未央” |
| 守护者的口吻 | 同一状态机、不同措辞：“我在守望着”“正在记住这一切”“镜中起雾了”“所剩无几了♭”“晚安♭”；摸摸她时“……谢谢你♭”。全部为原创文案，不引用游戏文本 |
| 烛火与雾 | 英雄区底部一层薄雾；卡片顶边一道月光描边 |

以上全部是静态图形或一次性栅格化的图片；唯一在动的仍是她本人（Core Animation 关键帧）。
开发中发现两处浪费并已修正：新月标记原用路径布尔运算、每次重绘都重算一次，改为 SF Symbol；
镜面遮罩只在开关变化时才触发重新布局。

### 0.8.2：更浓的二次元与交给渲染服务器的动效

| 新增 | 做法 |
|---|---|
| Galgame 对话框 | 英雄区底部：角色名牌 + 「台词」逐字显示（每次台词变化只打一次字）+ 说完后的 ▼；平静状态也有自己的台词，对话框从不空着 |
| 角色动作 | 肖像由“三格一拍”改为插值的缓慢漂浮与呼吸（约 24fps）；生气的颤抖仍保持逐格（8fps，那正是动画的“气鼓鼓”）；换表情时轻轻一弹 |
| 夜的空气 | 四片玫瑰花瓣沿 S 形缓缓飘落、六颗星（金 / 霜蓝）闪烁、每 7.5 秒一道流光划过镜面 |
| 装饰 | 镜框顶部的深红缎带、英雄区底边的裙边蕾丝（扇贝边 + 小孔）、夜想标题后的菱形饰线 |
| 互动 | 摸摸她时冒出三颗爱心（两套主题都有）；切换标签时呆毛弹一下 |

**轻量化：** 花瓣、星光、流光、角色动作全部是 Core Animation 动画，一次交给渲染服务器后由它自己播放，
App 进程不为任何一帧醒来；每个动画都声明低帧率（多数 12fps），窗口服务器的合成量也随之降低；
无人观看或关闭动效时直接移除动画。关闭窗口时释放角色、贴纸与星空位图缓存（菜单栏常驻时不再占用）。
另修正打包脚本：发布包检查原用 `rg`，在 `/bin/bash` 下不存在，检查一直被静默跳过；改为 `grep`。

## 第三主题：晨曲（Aubade）· 白天的她（`Aubade.swift`，0.8.3）

夜想是长夜月——三月七的“镜中人”、长夜里的月——的主题；晨曲是它的白天：三月七本人。
设置 → 外观 → 主题 现在有三个选项：猫娘观测所 / 晨曲 / 夜想。晨曲始终为浅色，夜想始终为深色。

| 设定 | 界面里的样子 |
|---|---|
| 爱拍照、随身带相机 | 首页英雄区：她在一张拍立得（方形）照片里——白色相纸、底边留白印着当天日期“MM.dd ☆”、晨光天空作底、一条和纸胶带斜贴在顶边。照片静止，她在照片里漂浮（Core Animation，和夜想的镜中肖像同一套） |
| 领口的六瓣花 | 标记换成六瓣冰花（樱粉花瓣 + 冰蓝花心）；选中的标签药丸上别着这朵花，每次切换转六分之一圈 |
| 冰属性 | 额度告急时爆炸框换成冰晶迸裂（与夜想相同的冰），但不裂镜纹——镜子是长夜月的 |
| 相册 | 英雄区底边一条胶片齿孔带（夜想是蕾丝）；小票是贴进相册的票据：冲孔票边、角上和纸胶带、空白处金色与冰蓝的闪光 |
| 开朗的口吻 | 台词以聊天消息出现：圆形头像 + 名字 + 气泡，新台词前先显示一拍“• • •”。“我在旁边看着哦”“咔嚓，记下来了！”“镜头起雾了…”“额度快见底啦！”；摸摸她时“嘿嘿，被你发现了☆”。全部为原创文案，不引用游戏文本 |
| 快门 | 小票的拟声字由收银机的“叮♪”换成快门“咔嚓☆”；店名“晨曲 · 晴空照相馆”；菜单栏图标是相机 |

配色取自她的贴纸图集（对抠出的人物做 k-means 取色）：发色的樱粉（标记处加深为 `#E07AA8`，保证在白底上看得见）、
裙子与线稿的藏青 `#4D5076` / `#343240`、外套与冰的冰蓝 `#77A4E3`、发梢的薰衣草、“！”的金色。

**角色包。** 她的图集每格是深色底，直接放到浅色页面上会是一块块深色方块，所以晨曲的角色包用 `--cutout`：

```sh
python3 scripts/make-character-skin.py 图集.png --name <包名> --title "<显示名>" \
    --map moods.json --skin aubade --cutout
```

`--cutout` 用 macOS 自带的 Vision 主体抠图（与“照片”App 的“拷贝主体”相同，本机运行，不上传）把人物从底色上取下，
烘焙成带白色模切边和一层柔和阴影的贴纸（480px 大图、200px 小图），另做一枚粉色描边的圆形头像给聊天消息用。
`skin.json` 新增 `"skin"`（属于哪个主题）与 `"style"`（`portrait` 肖像 / `sticker` 贴纸）；旧角色包没有这两项，
按夜想、肖像处理。图集里的“？”“！”“Zzz”等符号不属于主体，抠图时会被去掉——界面自己的漫画符号代替它们。
与夜想一样，角色图只放在 `~/Library/Application Support/AIMonitor/Skins/`，脚本拒绝写进 git 工作树。

**轻量：** 晨曲没有环境动画层（夜想的花瓣、星光、流光它都没有）——晴天的页面是静的。所有装饰是静态形状或一次性栅格化的图片；
唯一在动的是照片里的她（渲染服务器播放）、切换标签时花转一下、新台词前的一拍“• • •”。

## 猫娘贴纸（`MascotArt.swift`）

原图是透明底黑线稿，放在彩色卡片上只像涂鸦。每个姿势在首次使用时烘焙一次：

1. 闭合线稿缺口（方形膨胀）→ 从外侧泛洪 → 泛洪到不了的区域即角色本体，再腐蚀回去；
   半径自适应：面积增益超过 15% 才用大半径（早期较松的 angry / pounce 需要）。
2. 本体外扩数像素（八边形膨胀，近似圆角刀线）印成白边，带一层柔和阴影。
3. 原线稿以暖墨色 `#322B28` 叠在最上层。

三层合成为**每个姿势一张位图**并缓存。8fps 的猫娘动画仍然只移动一张图，没有实时模糊、蒙版或额外图层；
不新增任何图片文件，新增姿势依旧是“一张 PNG + 一个枚举值”。贴纸在浅色/深色下印刷一致。

## 轻量化约束

- 没有任何 `repeatForever`：常驻循环动画会把 SwiftUI 渲染钉在屏幕刷新上（历史实测 14.5% vs 2.0%）。
- 没有 material/模糊。卡片阴影是**每种圆角只画一次的九宫格图片**，拉伸使用：
  SwiftUI `.shadow` 会为每张卡片离屏模糊并常驻，首页十几张卡片实测约 20 MB 内存、启动时一秒多 CPU。
- 集中线、网点、纸纹都只栅格化一次再复用（与漫画页版相同）；冲击爆炸框只在额度转为告急时出现一次。
- 滚动渐显与视差只在滚动时计算，静止页面零成本。
- 会话“多久前”由独立的 `TimelineView` 驱动，只刷新这一个标签；秒级每秒、分钟级每 10 秒、小时级每分钟；
  **无人观看时停止计时**，重新看到窗口时立即重算。之前整行卡片每秒重绘一次，窗口在后台也照跑。
- “是否有人在看”由全页唯一的 `Attention` 对象跟踪（App 在前台且窗口未被遮挡/隐藏）。
  以前每只猫各自订阅 6 个系统通知，页面上有十几只猫，任何窗口（包括菜单栏）的遮挡变化都会重绘全部。
- 首页猫娘的“三格一拍”（8fps）交给 **Core Animation** 播放（`MascotCels`：离散关键帧，逐格停顿而非补间）。
  以前用 SwiftUI `TimelineView` 每秒唤醒 App 8 次重建视图图、渲染、提交，窗口被看着时约占一成核心；
  现在关键帧一次交给渲染服务器，由它自己翻格，App 进程休眠。
  无人观看、减弱动态效果、App 动画开关关闭、低电量时静止。
- **不要在含动画子视图的地方用 `ViewThatFits`**：它为测量会同时保留所有候选视图，
  两只 8fps 猫一起走表，每一帧都触发重新测量并重排整页——开发中实测约占四分之一个核心。
  首页改用自定义 `HeroRow` 布局，只在尺寸变化时决定猫娘大小。
- 设置 → 外观 → 动画：关闭后所有装饰动效停止；系统“减弱动态效果”与低电量模式始终优先。

## 实测（2026-09-23，同一台机器，同一份合成数据，Release 构建，每次静置 30 秒取进程 CPU 时间）

| 条件 | 漫画页版（0.7.2） | 猫娘观测所 |
|---|---|---|
| 窗口在屏幕上、猫娘在动（`--attended`） | 5.9% / 9.1% / 13.4% | 1.5% / 0.9% / 6.7% |
| 无人观看（App 不在前台） | 0.4% | 0.03% |
| 常驻内存 RSS | 约 110 MB | 约 127 MB（一次 146 MB） |
| Release 可执行文件（strip 后） | 1.47 MB | 1.70 MB |
| 图片资源 | 1.0 MB | 1.0 MB（未新增图片） |

两版的演示窗口都已改为不读取真实日志（见下文），数字才可比；此前测得的“两版都约 70%”
实为演示窗口把真实日志全量同步进内存库。内存多出的约 17 MB 来自多一套字体（衬线标题）、
贴纸位图与漫画纹理；CPU 数字随系统焦点状态波动，表中列出全部样本。

### 0.8.1 两种主题（同上条件；测量窗口不接收点击，避免把操作算进去）

| 条件 | 猫娘观测所 | 夜想（长夜月角色包） |
|---|---|---|
| 窗口在屏幕上、角色在动 | 0.4% / 0.9% / 1.5% | 0.4% / 3.2% / 3.6% |
| 常驻内存 RSS | 约 122–127 MB | 约 142–145 MB |

夜想多出的内存来自角色包的肖像与头像位图（按需加载、只缓存用到的格）和星夜纹理。
此前一次“夜想 37%”的读数，采样里出现了设置页与时间线页的渲染：演示窗口弹出后被点击了，
测到的是操作而不是静置；此后演示窗口在 `--attended` 下不抢焦点、不接收点击。

## 验证

```sh
swift test --scratch-path /tmp/aimonitor-station-build
swift build --scratch-path /tmp/aimonitor-station-build
/tmp/aimonitor-station-build/debug/aimonitor-app --render-review /tmp/aimonitor-station-review
/tmp/aimonitor-station-build/debug/aimonitor-app --demo-window
```

`--render-review` 与 `--demo-window` 仅在 DEBUG 构建存在，使用内存数据库及模拟数据，不扫描用户日志、不读凭据
（`MonitorModel(readsSources: false)`：此前任何一次刷新——点标签页、切换范围——都会把真实日志
首次全量同步进内存库，占掉大半个核心，并让性能测量失真）。
`--demo-window --attended` 强制“有人在看”，用于测量猫娘动画时的开销。
前者检查动效策略与偏好持久化，并渲染中英文、浅深色、窄/宽窗口与各页面；后者打开真实窗口供肉眼检查与性能采样。
打包脚本会拒绝把这两个入口带进 Release。截图不代表真实账户额度。

## 小票（日结单）· 0.8.3

新增第五个标签页「小票 / Receipt」：把今日或近 7 天的 token 花费打印成一张超市小票。

| 设计 | 落在代码里 |
|---|---|
| 商品 = 模型 | 数量 = token，单价 = 实际折算的 $/百万 token，金额 = API 标价折算 |
| 未定价不算 $0 | 未定价的模型照样列出（无价格），计入 token 合计，不计入金额合计，并写明“N 项未定价” |
| 与首页一致 | 1 天的金额 = 首页“今日”的同一条查询，测试固定为分毫不差 |
| 7 天 = 日结明细 | 每天一行（本地日历日，夏令时也按日历切），没用的日子印“休息”，不是 $0 |
| 零 token 不是商品 | Claude Code 的 `<synthetic>` 记录（本地生成、0 token）不上小票 |

### 走纸交给 Core Animation（0.8.3）

SwiftUI 的动画每一帧都在主线程上推进：每帧更新视图图与提交图层，走纸 2.5 秒就是 300 帧的主线程工作。
现在小票是一个独立的托管视图（`PaperRun`），放在以出纸口为上沿的裁切层里；整段棘轮走纸是该层
`sublayerTransform` 上的一条关键帧动画（每步“走—停”两段，走的一段缓入缓出），一次交给渲染服务器，
之后 App 不再为走纸醒来；点击跳过是一条基本动画，切刀落下是一条与 SwiftUI 同参数的弹簧动画。
`--print-film` 用同一套位置函数逐帧绘制，所以录像与实机一致。

两处坑已处理：首次布局时 SwiftUI 会用一个“试探高度”（约 1950pt）问尺寸，按它排的关键帧会快 3 倍——
现在高度一变就以同一起点重新排关键帧；嵌套的托管视图会吃掉滚轮——现在滚轮事件不命中小票，
直接落到页面的滚动视图上（2026-10-05 在已安装的 App 上用真实滚轮验证）。
另外：日期格式化器按语言与格式缓存（一张 7 天小票原来要新建约 10 个）、7 天的进度条改为形状而非 `GeometryReader`。
